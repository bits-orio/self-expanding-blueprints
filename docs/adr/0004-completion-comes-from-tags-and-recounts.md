# Completion comes from tags and recounts, never from a counter

Every entity ghost a stamp creates is tagged `seb_instance = <id>` after `build_blueprint` returns, and every ghost, tile ghost and item request is registered with `register_on_object_destroyed`. Built events that carry the tag attach the new entity to its instance. Any registered object vanishing marks the instance dirty, and once events go quiet (30 ticks, at most 120 after the first) a recount searches the footprint for what is left. Zero left with every ghost accounted for means complete; zero left with ghosts missing means incomplete.

Spike S3 confirmed the event coverage (`dev/spikes/s3-tracking/FINDINGS.md`): robots and script revives hand the tags back, a ghost's destruction always arrives after its built event, tile ghosts have unit numbers and can be registered, and item requests exist inside the built handler but announce neither creation nor delivery. Counts that are decremented drift (Constructron's did, at least six times); a recount cannot.

Supporting choices:

- **Instances keep `LuaEntity` references to what they built.** Retirement needs them, and `game.get_entity_by_unit_number` only works for prototypes flagged for it. Built entities get new unit numbers, so the ghost's number cannot stand in.
- **Item requests are watched from the built event.** Their destruction is the only sign of delivery, so a primed design completes only once its modules are in.
- **Tile ghosts are counted by unit number.** Matching them by position key made the recount about eight times slower. Tile positions are still kept, because built tiles and their removal orders have no other handle.
- **A tag alone proves nothing.** Blueprints taken over in-flight ghosts copy their tags, so a built entity joins its instance only if it stands inside the footprint and belongs to the instance's force. Tags are also stripped from blueprints in `on_player_setup_blueprint`, so a library copy never carries an instance id around.
- **Death ghosts are tagged and watched.** A tracked entity that dies leaves an untagged ghost; `on_post_entity_died` tags it, so the rebuilt entity is tracked again, and registers it, so a ghost removed unbuilt ends the instance as incomplete instead of leaving it building forever. Every tagged ghost a recount finds is registered as well (registering twice returns the same number).
- **Upgrades and fast-replaces are adopted.** They mine a tracked entity and build its replacement untagged, at the same position, in the same tick. The mined event remembers where the tracked entity stood (for robots, only one marked for upgrade), and the build event adopts what lands there.
- **Silent revives are adopted by the recount.** A script that revives a ghost without `raise_revive` raises no built event. When a recount finds no ghost left but entities missing, it adopts an untracked entity only where it stands exactly where a ghost of that name stood (the stamp records each ghost's position while the instance builds), before calling the instance incomplete. A player's own entity elsewhere in the footprint is never taken, and a name whose prototype is gone with a removed mod is skipped rather than searched for.
- **Laid tiles and delivered items count as progress.** A recount whose count left has dropped resets the stall clock, so an instance finishing its tiles is never marked stalled.
- **Recounts are not budgeted.** One costs about 0.05 ms per 100 entity ghosts and 0.04 ms per 100 tile ghosts (spike S3), and runs once per instance after its events go quiet, not every tick. DESIGN.md's time-sliced finds wait until a measurement says they are needed.
- **Retirement orders exactly the instance's own entities and tiles.** Unbuilt entity and tile ghosts are destroyed, built entities and tiles are ordered for deconstruction, and the instance is retired when the last of them is gone.

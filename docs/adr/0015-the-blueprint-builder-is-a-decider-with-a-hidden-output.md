# The blueprint builder is a decider with a hidden output

The circuit layer needs an entity with an input that a program writes requests to and an output the mod writes answers to. A constant combinator has one connector, so its own answers would mix with the program's requests on the same wire. A decider combinator has two connectors, but its output is computed by the engine from its settings and cannot be written by script.

So the builder is a decider combinator underneath, for its two connectors and its look (tinted), with a hidden constant combinator placed on it and joined to its output connector by script wires, which players can neither see nor cut. The mod reads the decider's input red and green summed: the verb signals one by one with `get_signal` on every read, and the whole input with `get_signals` only when it takes a request, charged to the builder's team by the signals it copies (the griefing review measured a whole-input read of 300 signals at about 130 µs, every 12 ticks per builder). It writes answers into the hidden combinator's section. The decider's own settings stay empty: opening it shows the builder's window instead, with every signal it understands, and players cannot set conditions that would add to its output.

A request is a verb signal whose value is a request number, held with its inputs until the builder answers ACK with that number. The builder runs one request at a time and does not acknowledge the next until the current one is done, so the queue depth is one and a program simply keeps holding its next request. Grow is a long request: DONE comes when its project finishes, Pause on the input pauses it and Stop stops it, and meanwhile the output carries the project's status and the next copy's bill of materials.

There is no engine event for a circuit network changing, so wired builders are read every 12 ticks, through the same due-tick queue as everything else, and only while builders exist; each read is charged to the builder's team (D44).
